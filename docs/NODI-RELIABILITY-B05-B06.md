# B05 / B06 filesystem identities and independent records

Stacked on B10 / PR #8. Reuses B04's native object identity: Windows volume/file ID/creation time; Darwin device/inode/birth time. Receipt keys and optional A2 `source_object` now recognize aliases of the same object without folding unrelated case-sensitive paths or comparing contents. Newly recorded identities reject recreated sources. Legacy receipts are matched using SameFile and upgraded only during successful acknowledgement, including stamping matching path-keyed copies. Dry-run never migrates state.

Download records use repository + version + destination object in their keys. Multiple repositories and outputs cannot overwrite each other. Existing `VERSION.json` records remain readable; repository names are compared case-insensitively. Latest selects existing matching objects by download time, with deterministic path ties. Missing/deleted destinations do not hide other surviving records. Concurrent writes use independent files.

RED: case-alias send loses custom name; repository and output-path collisions lose the first record. GREEN: these three cases pass, plus legacy receipt migration, recreated-source refusal, twelve concurrent records, and old download format. Full Windows tests/vet PASS. [Evidence](reliability/batch/b0506). The case-sensitive negative test is skipped on this host's insensitive NTFS; that specific scenario is NOT VERIFIED locally and requires a case-sensitive CI fixture. Short-name alias and platform default roots are exercised by Windows temporary paths; deliberately created additional aliases and case-sensitive NTFS are NOT VERIFIED.

Compatibility: old config/receipt/download/journal records still decode; optional fields only, manifest schema remains 1. A legacy record contains no historical filesystem generation: SameFile can prove its currently referenced object but cannot prove it was not replaced before migration. Such history cannot be reconstructed. Once upgraded, generation checks apply. Local source file IDs are not a distributed ownership credential. Hardware power loss and physical-device acceptance remain NOT VERIFIED.
