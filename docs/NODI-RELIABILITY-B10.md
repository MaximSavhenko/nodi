# B10 installer rollback

Stacked on B04 / PR #7. Installers check SHA-256, native executable header, runtime version/platform, optional requested local version and exact remote release version before replacement. Candidate is copied into sibling staging and rechecked. Windows takes an exclusive file lock, uses File.Replace with a previous-version backup on NTFS, and restores the backup after a failed postcheck. macOS takes an exclusive mkdir lock, keeps a hardlink backup of the old inode, atomically renames the sibling candidate and restores from that backup after failed postcheck. Unsupported operations fail without a per-file overwrite fallback. Prior binaries remain available in printed transaction paths. Profile/PATH edits occur after verification.

RED on the original installer: checksum-valid exit-7, invalid version text, wrong reported platform, and installed-only postcheck failure all lose the old executable. GREEN: all four retain identical old SHA. Windows locked-target and explicit wrong-version cases also preserve the old binary. Tests build fictional binaries, invoke the real installer and target disposable directories; macOS uses a disposable child-process home. No user installation or production credentials used.

Evidence: [RED](reliability/batch/b10/b10-red.log), [GREEN](reliability/batch/b10/b10-green.log), [full tests](reliability/batch/b10/b10-tests.log), [vet](reliability/batch/b10/b10-vet.log). Windows native PASS. macOS execution and race require this PR's native CI. Installer options `-Version` / `--version` are additive for local bundles; existing invocation syntax remains supported. Remote release always supplies the expected version. Local bundles without that option require a valid stable runtime version/platform but have no independent expected version.

Limits: installer kill/hardware power-loss and rollback-failure fault injection NOT VERIFIED. Backup is kept before replacement; Windows filesystem replacement must support File.Replace. An interrupted macOS mkdir lock needs manual exact-path inspection before removal. Old binaries/transactions are retained, with no broad automatic cleanup. Existing 0.3.0 upgrade/completion CI is preserved; 0.4.1 runtime format is accepted. No release or active install is updated by this work.
