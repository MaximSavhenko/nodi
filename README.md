# Nodi CLI 0.2

Nodi передаёт инженерные пакеты между Windows и macOS через приватный репозиторий GitHub и его Releases. На компьютере получателя нужны только Nodi и доступ в интернет. CAD, Git, Go, VPN и домашний сервер не нужны.

Команды запускаются вручную. Nodi не проверяет технологическую пригодность чертежей: `released` означает явный статус публикации, заданный автором пакета.

## GitHub и пакетные менеджеры

- [nodi](https://github.com/MaximSavhenko/nodi) — публичный исходный код (MIT), проверки и бинарные релизы.
- [homebrew-nodi](https://github.com/MaximSavhenko/homebrew-nodi) — публичный Homebrew tap.
- [nodi-packages](https://github.com/MaximSavhenko/nodi-packages) — приватное хранилище пакетов; требуется доступ пользователя.

Стабильная [версия 0.2.1](https://github.com/MaximSavhenko/nodi/releases/tag/v0.2.1) добавляет Tab completion, локальную привязку проекта, SHA-256 status и публикацию с автоматическим версионированием. Windows и обе архитектуры macOS, Homebrew upgrade 0.1.0 → 0.2.1 и приватная передача Mac → Windows прошли проверки: [NODI-03](docs/NODI-03-STATUS.md). [Winget PR 0.1.0 #450627](https://github.com/microsoft/winget-pkgs/pull/450627) сохранён; пока он ожидает CLA владельца и проверки Microsoft, manifests 0.2.0/0.2.1 подготовлены отдельно и не заменяют существующий PR.

macOS, Apple Silicon и Intel:

```sh
brew install MaximSavhenko/nodi/nodi
nodi version
nodi help
brew update
brew upgrade MaximSavhenko/nodi/nodi
brew uninstall MaximSavhenko/nodi/nodi
```

Formula устанавливает готовый бинарник из ZIP с проверкой SHA-256; Go для установки не нужен. Tap автоматически обновляется каждый час только из стабильного релиза с подтверждающим `validation.json`. Homebrew должен быть установлен отдельно.

Windows, **после принятия пакета в официальный источник winget**:

```powershell
winget install --id MaximSavhenko.Nodi --exact --source winget
nodi version
nodi help
winget upgrade --id MaximSavhenko.Nodi --exact --source winget
winget uninstall --id MaximSavhenko.Nodi --exact
```

WinGet управляет portable ZIP, командой `nodi` в PATH, установленной версией и удалением. Пока пакет не находится в официальном источнике, используйте терминальный установщик ниже. Локальная проверка manifest и установка из manifest не означают доступность пакета в каталоге Microsoft. Актуальные результаты: [NODI-03](docs/NODI-03-STATUS.md); история первого выпуска: [NODI-02](docs/NODI-02-STATUS.md).

При переходе с терминального установщика на winget удалите прежний `%LOCALAPPDATA%\Nodi\bin\nodi.exe` и его запись пользовательского PATH по инструкции удаления ниже. Затем установите пакет через winget и откройте новый терминал. Так обновления winget будут запускать управляемый им бинарник; скачанные проекты и конфигурация сохранятся.

## Повседневная работа

Один раз привяжите папку к проекту. `init` берёт репозиторий из `nodi config`; `--repo OWNER/PRIVATE-REPO` позволяет задать другую привязку. Токены остаются в пользовательском хранилище credentials и не записываются в `.nodi/project.json`.

```sh
cd ~/Desktop/MacStand
nodi init macstand
nodi status
nodi publish
```

Команды `status` и `publish` находят ближайшую `.nodi/project.json` также из вложенных папок. Повторный `init` сохраняет настройки. В config schema 1 находятся project, repository и, после успешной публикации, last_version; допускаются description и строковые metadata без секретов. Скрытая `.nodi` не входит в пакет. До первой публикации нужен отдельный write credential: `nodi auth login --write`.

`status` ничего не записывает: сканирует поддерживаемые файлы и показывает Added/Modified/Deleted относительно последней полной удалённой версии, включая draft при наличии write credentials. При отсутствии связи или credentials явно выводит NOT VERIFIED; кеш completion за актуальное удалённое состояние не выдаётся. При использовании только read credentials сравнение ограничено released-версиями, и непроверенные drafts отмечаются отдельно.

`publish` определяет проект и файлы, сверяет SHA-256 с GitHub, показывает preview и спрашивает `Publish? [y/N]`. По умолчанию статус draft. Первая версия — 0.1.0, затем PATCH; `--minor` и `--major` увеличивают соответствующую часть и обнуляют младшие. Учитываются версии и черновики с других компьютеров; локальный last_version не управляет версионированием.

```sh
nodi publish --minor
nodi publish --major
nodi publish --status released
```

Для автоматического `--status released` после ответа `y` требуется набрать `release PROJECT VERSION`, указанные в preview. Это сознательная производственная публикация, а не инженерная проверка. Старый явный синтаксис `nodi publish PROJECT PATH --version X.Y.Z --status released` остаётся без интерактивного диалога: явные версия, источник и статус уже задают намерение автора.

Без изменений выводятся `No changes detected. Nothing to publish.`; release не создаётся даже с --minor/--major. Изменение только времени файла не считается изменением. Если не осталось поддерживаемых файлов, пустой пакет не создаётся. Description/metadata без изменения файлов также не создают новую версию.

Перед загрузкой повторно проверяются удалённое состояние и локальные файлы. Git-тег резервируется атомарно, поэтому одновременная публикация одной версии не перезапишет данные. При конфликте операция прекращается: повторите её, чтобы получить новое состояние и preview. При сетевой ошибке/неполной загрузке новая версия автоматически не выделяется. Сохранённый неполный draft или тег без полного Release требует проверки на GitHub; автоматическая публикация блокируется, пока последняя версия не разрешена вручную. CLI не удаляет её и не выполняет автоматический retry.

## Tab completion и версия

```sh
nodi -v
nodi --version
nodi completion
```

`version`, `-v` и `--version` показывают реальную версию бинарника и платформу. `completion` выводит инструкции; с именем оболочки — только скрипт. Подсказываются команды, auth login/logout, флаги, draft/released, проекты, версии для --version и пути для publish/--output/--metadata. Проекты и версии берутся через GitHub API с кешем на 60 секунд, привязанным к repository, роли и fingerprint credentials. Для publish используются write credentials и видны drafts; get использует read credentials и только выпущенные версии.

Включить **только в текущем терминале**, без изменения shell profiles:

```zsh
autoload -Uz compinit; compinit
source <(nodi completion zsh)
```

```bash
source <(nodi completion bash)
```

```powershell
nodi completion powershell | Out-String | Invoke-Expression
```

Homebrew автоматически устанавливает `_nodi` и bash completion в стандартные каталоги. Если оболочка уже использует `brew shellenv` и compinit/bash-completion, Tab доступен после открытия нового терминала. Для zsh `brew shellenv` должен выполняться до compinit; настройка зависит от существующего shell framework. [Инструкция Homebrew](https://docs.brew.sh/Shell-Completion).

Winget ZIP содержит completion scripts, а встроенная команда работает и при установке одного exe. Portable winget не меняет PowerShell profiles: включите completion командой выше. Для постоянного подключения после просмотра скрипта самостоятельно добавьте соответствующую строку в `$PROFILE`, `~/.zshrc` или `~/.bashrc`. Nodi не изменяет эти файлы.

Tab не запрашивает токен и не раскрывает credentials. Общий сетевой таймаут 1,5 секунды. При сетевом сбое используется доступный кеш, без кеша — пустой результат. Подсказки из кеша могут быть устаревшими и не заменяют проверку перед publish/get. При смене repository, роли или токена чужой кеш не используется. Ошибки completion подавляются; терминал продолжает работу.

## Установка через терминал

В этой локальной поставке самостоятельные программы находятся в `dist/`:

- `nodi-windows-amd64.exe` — Windows x64.
- `nodi-darwin-arm64` — Apple Silicon.
- `nodi-darwin-amd64` — Intel Mac.
- `SHA256SUMS` — контрольные суммы трёх программ и трёх ZIP-пакетов.

Сначала прочитайте исходный код установщика. Go нужен разработчику для сборки, но не пользователю для установки и работы.

**Windows, PowerShell:**

```powershell
cd C:\projects\nodi
Get-Content .\scripts\install-windows.ps1
.\scripts\install-windows.ps1 -BundleDirectory .\dist
nodi version
```

Установка: `%LOCALAPPDATA%\Nodi\bin\nodi.exe`, пользовательский PATH. Установщик проверяет SHA-256 и запускает `version`. Если команда не появилась в другом терминале, откройте его заново. Администратор не нужен. При запрете выполнения скриптов вашей организацией используйте разрешённый организацией способ; установщик не изменяет ExecutionPolicy.

**macOS, Terminal/zsh:** скопируйте `dist/` и `scripts/install-macos.sh` на Mac, сохранив структуру папок.

```sh
cat scripts/install-macos.sh
sh scripts/install-macos.sh --bundle ./dist
export PATH="$HOME/.local/bin:$PATH"
nodi version
```

Установка: `~/.local/bin/nodi`; shell profiles по умолчанию не изменяются. Для текущего терминала используйте `export PATH` выше. Только явный `--add-path` разрешает установщику добавить строку PATH в `~/.zprofile`; completion подключается отдельно. На Mac применяются обычные правила Gatekeeper; установщик не снимает quarantine, не отключает защиту и не подписывает программу.

Установка или обновление до подтверждённой версии 0.2.1:

```powershell
.\scripts\install-windows.ps1 -Repository MaximSavhenko/nodi -Release v0.2.1
```

```sh
sh scripts/install-macos.sh --repo MaximSavhenko/nodi --release v0.2.1
```

Windows поддерживает приватный релиз CLI через переменную `NODI_INSTALL_TOKEN`; macOS сетевой режим рассчитан на публичный доверенный релиз, для приватной поставки используйте локальный комплект. Токены никогда не передаются аргументом команды. Контрольная сумма из того же доверенного релиза проверяет целостность; отдельной криптографической подписи поставки в v0.1 нет.

## Первая настройка GitHub

1. Используйте подготовленный **private** репозиторий `MaximSavhenko/nodi-packages` с начальным коммитом/README, либо свой отдельный приватный репозиторий. Исходный код Nodi храните отдельно. Nodi не создаёт облачные репозитории автоматически и отказывается работать с публичным хранилищем.
2. Создайте fine-grained Personal Access Token только для выбранного репозитория. Для получения: **Contents: Read-only**. Для публикации на домашнем компьютере: отдельный токен **Contents: Read and write**. Стандартное право Metadata оставьте включённым. При необходимости подтвердите доступ организации/SSO. Не выдавайте права на остальные репозитории.
3. Выполните настройку на каждом компьютере:

```text
nodi config --repo MaximSavhenko/nodi-packages
nodi auth login
```

Вставьте токен в скрытый ввод и нажмите Enter. На компьютере автора отдельно:

```text
nodi auth login --write
```

Windows хранит токены в виде DPAPI-данных, привязанных к текущему пользователю. На macOS MVP использует файл с правами `0600` в каталоге `0700`, а не Keychain. Конфигурация без токенов: Windows `%APPDATA%\nodi`, macOS `~/Library/Application Support/nodi`. Не выбирайте для конфигурации общий или синхронизируемый каталог.

Альтернатива для CI/временной сессии: `NODI_REPO`, `NODI_READ_TOKEN`, `NODI_WRITE_TOKEN`. Переменная `NODI_CONFIG_DIR` задаёт отдельный каталог конфигурации и локальных записей. Не записывайте токены в исходники, команды с литералами токенов, `.env` проекта или логи. Read-токен не заменяется автоматически write-токеном. Удаление сохранённых данных: `nodi auth logout`; токены в переменных окружения удаляются отдельно, отзыв прав выполняется на GitHub.

GitHub применяет реальные права токена. Выбор `--write` определяет слот хранения и не увеличивает права. GitHub предоставляет черновики только пользователям с правом push; для `list --all` и `info --all` Nodi использует write-токен. [Документация Releases API](https://docs.github.com/en/rest/releases/releases).

## Команды

```text
nodi version
nodi help
nodi list
nodi list --all
nodi info macstand
nodi info macstand --all
nodi get macstand
nodi get macstand --version 1.0.0
nodi get macstand --output "D:\Engineering\macstand-1.0.0"
nodi open macstand
```

`list` показывает последнюю по числовой версии запись для каждого проекта; `info` — все доступные версии, описание, форматы, размер ZIP, дату подготовки публикации и дополнительные метаданные. Релизы стороннего формата игнорируются. Список GitHub читается постранично. Проект: латинская строчная буква, затем строчные буквы/цифры/дефисы, до 63 символов; системные имена Windows запрещены. Версия: `MAJOR.MINOR.PATCH`, без `v`, ведущих нулей и prerelease-суффиксов. `1.10.0` новее `1.9.0`.

`get` без версии выбирает максимальную выпущенную версию. По умолчанию папка — `Desktop/Nodi/PROJECT/VERSION`. Windows Desktop определяется через Known Folder API, включая перенаправление в OneDrive; macOS — `~/Desktop`, включая стандартный iCloud Desktop. `--output` — **точная новая папка результата**, без добавления проекта/версии. Любой существующий путь, включая пустую папку, отклоняется. Для второй копии выберите другой путь. `open` открывает последнюю по времени успешно скачанную и ещё существующую папку данного проекта, в том числе при использовании `--output`, без обращения к сети.

## Публикация

Подготовьте отдельную папку экспортированных производственных файлов. Поддерживаются `.dxf`, `.pdf`, `.step`, `.stp`, `.iges`, `.igs`, `.stl`, `.3mf`, `.svg`, `.dwg` (регистр расширения не важен). Другие файлы и скрытые каталоги/файлы исключаются; символические ссылки отклоняются. Файлы CAD-исходников и конфигурация не входят в пакет. Nodi не анализирует содержимое разрешённых форматов — автор проверяет, что в них нет секретов и ненужных данных.

Статус обязателен. Для черновика:

```text
nodi publish macstand ./manufacturing --version 0.1.0 --status draft
```

Для сознательно выпущенного пакета:

```text
nodi publish macstand ./manufacturing --version 1.0.0 --status released --description "Подставка, комплект экспортов"
nodi publish macstand ./manufacturing --version 1.0.1 --status released --metadata ./metadata.json
```

Метаданные — JSON-объект со строковыми значениями, например `examples/metadata.json`. Они публичны для всех читателей приватного репозитория; не включайте секреты. `released` не подтверждает материал, допуски, раскрой, режимы оборудования или согласование производства.

Каждая версия — отдельный GitHub Release, тег `macstand/v1.0.0`, вложения `package.zip` и `nodi-manifest.json`. Такой тег допустим в Git; слеш — часть имени тега, а не готовый каталог GitHub. Nodi индексирует теги вместе с манифестами. [Ограничения имён Git](https://git-scm.com/docs/git-check-ref-format), [Releases API](https://docs.github.com/en/rest/releases/releases).

Сначала создаётся `draft=true`, загружаются ZIP и JSON. Только после загрузок для `released` отправляется обновление `draft=false, prerelease=false`. Для Nodi draft остаётся `draft=true, prerelease=true`, а в JSON явно записан `status=draft`; prerelease сам по себе не обозначает производственную готовность. Черновик не доступен через `get`. Для выпуска после черновика публикуйте новую версию: автоматического продвижения/замены существующего релиза нет.

При ошибке загрузки черновик сохраняется для проверки на GitHub. Повторная публикация той же версии отклоняется. Если ошибка произошла при финальном обновлении статуса, результат может быть неопределён из-за потери ответа: сначала проверьте релиз на GitHub. Удаление/исправление черновика выполняется вручную; Nodi не удаляет удалённые данные. Манифесты с несогласованным статусом или отсутствующими файлами отклоняются.

## Целостность и ограничения

- Только HTTPS; загрузки с API могут переходить на HTTPS CDN, без пересылки токена. Nodi проверяет приватность репозитория перед чтением/публикацией.
- ZIP до 256 MiB, суммарная распаковка до 512 MiB, до 10 000 файлов; JSON до 4 MiB. Это ограничения Nodi; GitHub допускает release asset менее 2 GiB. [Ограничения GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).
- SHA-256 ZIP и каждого файла, размеры и состав проверяются до установки результата. Распаковка идёт в временную папку; неверные файлы не становятся результатом.
- Запрещены абсолютные пути, `..`, обратные слеши, потоки NTFS, системные имена, ссылки, дубли и различия путей только регистром. Существующая целевая папка не заменяется. Локальный злоумышленник с доступом к переименованию родительских папок во время операции не входит в модель защиты MVP.
- Транспорт не предоставляет цифровую подпись пакета. SHA-256 защищает целостность относительно манифеста; редактор репозитория может изменить и архив, и манифест. GitHub на стороне сервиса не превращается Nodi в неизменяемое хранилище.
- Нет фоновой синхронизации, самостоятельного автообновления CLI, resume-download, retry публикаций, работы с оборудованием или CAD. Сборки macOS не подписаны/notarized. Обновления программой управляются Homebrew/winget; статус включения в официальный winget указан отдельно.

## Обновление и удаление

Обновление: повторно запустите установщик с новым проверенным комплектом или доверенным релизом. Скачанные проекты и конфигурация сохраняются. Убедитесь, что выполняющийся `nodi.exe` завершён.

Windows: удалите `%LOCALAPPDATA%\Nodi\bin\nodi.exe` и эту запись пользовательского PATH. macOS: удалите `~/.local/bin/nodi`; строку PATH из `~/.zprofile` удаляйте, только если она не нужна другим программам. При необходимости выполните `nodi auth logout` до удаления. Проекты и конфигурация не удаляются установщиком автоматически.

## Разработка и проверки

Нужен Go 1.27.2. Зависимостей вне стандартной библиотеки нет.

```powershell
go test -cover ./...
go vet ./...
.\scripts\build.ps1
```

Для локального компилятора этой рабочей папки:

```powershell
.\.tools\go\bin\go.exe test -cover ./...
.\scripts\build.ps1 -Go "$PWD\.tools\go\bin\go.exe"
```

Флаги сборки: `CGO_ENABLED=0`, `-trimpath`, `-buildvcs=false`, пустой build ID, версия CLI из стабильного тега. Порядок файлов ZIP и время в ZIP фиксированы; манифест инженерного пакета содержит реальное время подготовки. GitHub Actions собирает три бинарника, запускает Go-проверки и точные release-бинарники на Windows, macOS ARM64 и Intel, затем публикует релиз только по тегу `vMAJOR.MINOR.PATCH`. Вложения сначала загружаются в draft; стабильный релиз открывается после подтверждённых native-проверок и `winget validate`. Существующие релизы не заменяются. Для локального `-race` нужен совместимый C-компилятор; CI запускает race-проверки на macOS.
