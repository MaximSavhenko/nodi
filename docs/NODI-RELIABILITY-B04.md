# B04 atomic directory installation and record recovery

Stacked on A4 / PR #6 (`019380b`). Windows uses MoveFile without replacement/copy flags; Darwin uses XNU renameatx_np syscall 488, RENAME_EXCL=4. Sources: [Apple syscall table](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/syscalls.master), [Apple flags](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/stdio.h). Unsupported platforms/volumes refuse installation. No per-file fallback. Sibling staging is fully extracted, hashed and files synced before commit. Cancellation and final parent checks precede rename.

Download installation saves a checksummed intent containing repository/manifest/destination and the staging filesystem object identity before commit. If the process fails after commit and before Record, repeating get can verify the same directory object and every manifest file and reconcile the record. Equal bytes in a different directory are insufficient. This introduces a small shared filesystem identity helper for NTFS (volume/file ID/creation time) and Darwin (device/inode/birth time); B05 reuses it for receipts. Intent and metadata are private local files; no extra file is placed in the delivered package.

RED: killed child leaves final directory with 1/1200 files on baseline. GREEN: same kill immediately after visibility leaves all 1200 correct files. Empty/nonempty/file concurrent destinations are preserved, cancellation leaves no final directory. Separate RED: Record failure after successful get makes retry refuse; GREEN: same destination reconciles from saved intent. Evidence in [batch/b04](reliability/batch/b04). Full local Windows tests/vet PASS; both Darwin cross-builds PASS. Native filesystem tests run in PR CI and must pass at the exact HEAD.

Limits: hardware power-loss/storage failure NOT VERIFIED. Directory rename atomicity depends on filesystem support; unsupported no-replace calls fail closed. A local writer can still alter ancestors after a path check. Interrupted precommit staging is retained on process kill; automatic broad cleanup is deliberately absent. Download intents do not adopt legacy folders. Active installations and real packages are untouched.
