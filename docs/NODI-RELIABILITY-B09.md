# B09 visible exclusions and exact selection

Stacked on B07/B08 / PR #10. Ordinary send reports the count, exact paths and reasons for exclusions, including unchanged sends. `send` and `publish` accept repeatable `--include RELATIVE/FILE` for an exact regular file; preview, packaging, rechecks and A2 recovery use the same selection rules. Inclusion is frozen in the journal, so retries must preserve the include flags.

Example: `nodi send ./delivery --include config.json --dry-run`, then the same command without `--dry-run`. Ordinary config.json can also be sent as an explicitly chosen individual file. Explicitly chosen build/dist directories are accepted as independent roots, with all child credential/key/hidden/private-config protections retained. Included paths cannot contain traversal, wildcards, hidden/service directories, credentials or key names. Nodi config aliases are protected by filesystem identity, not only textual path spelling. The name policy is still not a content-based secret scanner; users choose the delivery data.

RED: normal send omits config.json without reporting it; exact include is unsupported. GREEN: normal and unchanged outputs name omissions; preview and manifest include the same config; four hard-denial cases perform no remote mutation; selected upload interruption recovers with the original selection and rejects changed selection; build/dist roots and individual ordinary config work; private Nodi config is denied. Full Windows tests/vet PASS. [Evidence](reliability/batch/b09). Native CI required. Manifest schema and existing invocation syntax remain compatible; `--include` and completion entries are additive.
